# 位置保存修复与全应用界面走查

## 目标

改善移动端位置管理页面的新增入口，并修复“已写入数据却显示无法保存”的错误反馈。完成后，对应用所有用户可访问页面做一次功能与移动端界面走查，只修复走查中可确认的问题。

## 范围与交互

- “添加房间”和“添加存放点”使用专用的纯文字按钮样式：无实心背景、无圆角按钮外观，保留可触达的点击区域、禁用状态和键盘焦点可见性。
- 该样式仅应用于位置管理页的两个新增提交入口，不改变其他操作按钮。
- 房间或存放点的数据库写入成功后，立即清空表单并显示为成功；后续列表刷新失败不能改写为“无法保存”。
- 数据写入失败时保留现有的失败反馈，不清空表单。
- 为确保新增项立刻可见，刷新失败时将新建的记录合并进本地列表；同时尽力触发后台刷新。房间新增后，新增房间应立即可被存放点的房间选择器选中。

## 根因与实现边界

当前提交流程把写入和 `load()` 包在同一个 `try/catch`。写入已成功时，列表刷新仍可能因读取、关联数据或图片签名 URL 请求失败而抛出异常，随后被错误显示为保存失败；重新进入页面会重新读取，因此数据又出现。

实现将写入、表单更新和刷新拆开处理：写入异常才使用“无法保存”信息，刷新异常则保留已写入的本地状态并使用非阻断的读取提示。此改动不涉及数据库 schema、RLS 规则或实时订阅协议。

## 测试与走查

- 补充位置管理页测试：验证两个入口使用文字按钮类；验证写入成功但刷新失败时不显示保存失败，且表单清空与新增项仍可见；验证写入失败时维持失败提示和表单内容。
- 运行全量单元测试与生产构建。
- 在本地运行应用，对登录/首次设置、库存列表与筛选、库存详情、入库出库、扫码/商品照片、低库存提醒、成员管理、位置管理、桌面及移动导航、PWA 安装提示逐页核对：路由可达、主要操作可用、错误与空状态可理解、移动端没有被底部导航或浮动扫码按钮遮挡。
- 对走查发现的确定性问题，在本次分支一并修复并复跑相关测试；无法在本地确认的外部服务问题只记录，不臆测修改。

## 非目标

- 不重做全应用视觉系统或导航信息架构。
- 不引入新的 API、持久化状态库或端到端测试框架。
