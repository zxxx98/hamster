# 家庭资产（库存）记录 App 设计

## 目标与范围

构建一款响应式 Web 应用，帮助家庭共同记录可消耗家庭物品的库存，例如抽纸。用户能够通过扫描中国商品条码补全商品资料，记录数量与存放位置，并在库存不足时获得提醒。应用须同时适配 PC 和移动浏览器，并为日后封装为 Android / iOS 应用保留条件。

首版聚焦家庭库存，不覆盖记账、价格追踪、保质期管理、位置多级嵌套或成员权限分级。

## 平台和总体架构

- 前端采用 React、TypeScript 和 PWA，使用响应式布局适配 PC 与移动端。
- 后端采用托管数据库、对象存储和鉴权服务（建议 Supabase），保存共享数据、位置照片与会话信息，并支持多成员同步。
- 移动浏览器调用相机扫码；PWA 可安装到设备。后续可通过 Capacitor 等 Web 容器打包为 Android / iOS 应用，无需重写业务界面。
- 条码查询接入中国商品条码数据服务。结果用于预填名称、品牌、规格和包装图；服务失败或资料不准确时，不阻断用户手动录入或编辑。

## 家庭、成员和身份

家庭是数据隔离与共享的最小单元。

首次创建家庭的用户是家庭创建者，且仅创建者可以：

- 创建成员账号与初始 token；
- 重置成员 token；
- 撤销成员访问。

成员首次登录时输入账号和创建者提供的 token。服务验证通过后，客户端安全保存会话 token；之后打开应用时静默验证，成员无需再处理 token。库存、位置、提醒忽略和记录查看等业务权限对所有成员一致。

## 数据模型

### 商品

保存条码、名称、品牌、规格、包装图和可选分类。一个家庭内，同一条码只维护一份商品资料；成员手动修正后，家庭内后续录入复用修正后的资料。

### 房间和存放点

房间如“厨房”“卫生间”。存放点属于一个房间，如“水槽下方柜”“洗手台抽屉”。存放点可附一张示意照片。首版不支持层级位置。

### 库存项

库存项连接商品和存放点，保存当前数量、单位、低库存阈值和提醒忽略状态。相同商品放在不同存放点时，分别维护库存，方便查找和补货。

数量首版为非负整数；单位支持“包、盒、瓶、个”等预设或自定义文本。

### 操作记录

记录每次补货、取用和用完操作：操作者、发生时间、操作类型、变更前后数量及可选备注。记录不可被普通库存变更覆盖，用于家庭成员追溯。

## 核心流程

### 录入

1. 成员打开扫码器，读取条码。
2. 应用查询中国商品条码资料并预填商品信息；无结果、网络失败或信息不准确时，成员可手动填写或修改。
3. 成员选择房间、存放点、数量、单位和低库存阈值。
4. 保存库存项和“补货”操作记录，并同步给家庭其他成员。

也支持不扫码、直接手动新建商品与库存项。

### 日常库存变更

库存列表和详情中提供“补货”“取用”“用完”快捷操作。补货与取用输入数量；用完将该存放点的库存清零。取用数量大于现存库存时要求确认，默认不产生负数。每项操作均生成记录并更新共享库存。

### 查找和提醒

首页展示待补货的低库存项和近期操作。库存页可按房间、存放点、商品分类和低库存状态筛选。进入存放点可查看示意照片。

当库存小于或等于阈值时，库存项进入低库存状态。未补货到阈值以上、且未忽略时，每次打开应用都会在首页提示。成员可以忽略某个库存项的提醒；忽略只关闭提示，不改变其低库存状态，且可随时恢复。浏览器获得授权后，可以增补系统通知；首版不依赖系统通知来保证提醒可见。

## 错误处理和同步

- 相机权限被拒绝：说明原因，提供重新授权说明和手动录入入口。
- 条码查询失败：展示失败状态并保留手动录入入口。
- 网络暂不可用：提示同步状态；可将变更暂存本地，恢复网络后上传。
- 并发变更：后端按操作记录的服务器时间顺序处理，重新计算库存并将结果同步给成员。
- token 无效或被创建者重置/撤销：清除本地会话并返回登录页。
- 照片上传：限制安全的图片格式和体积，失败时不影响存放点文字信息保存。

## 关键测试范围

不为 UI 布局或视觉细节编写自动化测试。仅验证关键业务节点：

- token 只能访问所属家庭，撤销或重置后立即失效；
- 家庭之间的库存、照片和操作记录完全隔离；
- 补货、取用、用完正确更新数量，不会在未确认时产生负数；
- 阈值、忽略、恢复与补货后的提醒状态正确转换；
- 条码服务失败时仍可完成手动录入。

上线前在真实移动设备上人工验证相机扫码、PWA 安装和打开时的低库存提示；不纳入 UI 自动化测试覆盖范围。
